# json.library

Read, build and write **JSON** on the Amiga, from C and from **ARexx**, as one shared library in
`LIBS:`. JSON is the text format web services and many settings files use.

Nothing like it existed for the 68k Amiga (checked on Aminet, 2026-10-16): JSON came only as code to
build into each program (json-c), as an AmigaOS 4 library, or for AmiBlitz alone. A `.library`
can be used from any language, and from ARexx scripts.

## What it does

| | |
|---|---|
| **Reading** | text or a file into a tree; strict JSON (all 283 cases of JSONTestSuite right), or relaxed for settings files: comments, trailing commas, Latin-1 |
| **Errors** | line, column and what was wrong, in plain English |
| **Walking** | by name, by number, or by path: `JsonFind(root, "weather.days[0].temp")` |
| **Values** | text (UTF-8, or as Amiga Latin-1 with the nearest characters), whole numbers, fixed decimals (8.25 as 825), true/false |
| **No FPU needed** | no floating point at all; numbers keep their exact text |
| **Building** | objects, arrays, text, numbers, true/false, null; replace, remove, move |
| **Writing** | compact or pretty, to memory or a file; ASCII-only if wanted |
| **ARexx** | `JSONLOAD`, `JSONGET`, `JSONSET`, `JSONSAVE` and more, with paths |
| **Small machines** | no recursion (any depth on a 4 KB stack), no 32-bit multiply or divide in the loops, one memory pool a document; about 17 KB |

## For programmers

The [programmer's guide](docs/guide.md) explains how to use it, with a working first program in C
and ARexx examples; the [reference](docs/reference.md) describes every call in full.

```c
doc = JsonLoad("RAM:weather.json", 0, &err);
temp = JsonScaled(JsonFind(JsonRoot(doc), "days[0].temp"), 1, 0);   /* 8.25 -> 83 */
JsonFree(doc);
```

```rexx
CALL ADDLIB('json.library', 0, -30, 0)
j = JSONLOAD('RAM:weather.json')
SAY JSONGET(j, 'days[0].temp')
CALL JSONFREE(j)
```

## Building

`make` (bebbo's gcc): the library three times and `build/jsontest`. `make pctest` runs the core on
the PC under the address and undefined-behaviour sanitizers (`SUITE=.../JSONTestSuite/test_parsing`
adds JSONTestSuite); `make fuzz` runs it under libFuzzer.

**Which library to install** as `LIBS:json.library`:

| File | For |
|---|---|
| `build/000/json.library` | 68000, 68010 (every Amiga) |
| `build/020/json.library` | 68020, 68030, 68040, Emu68 |
| `build/060/json.library` | 68060 (no 64-bit multiply or divide, which the 060 only emulates) |

No FPU build: the library does no floating point.

- AmigaOS 2.04+ (dos.library 37); ARexx needs RexxMast running.
- The library has no C library inside (`-nostartfiles -nostdlib`); the build fails if libnix code
  gets in.
- **The table order is for ever.** `json.sfd` and `functable` in `src/lib.c` list the calls in
  the same order; new ones go at the end of both, and `JSON_REVISION` goes up. The first entry is
  ARexx's and must stay first.

## Files

| File | What |
|---|---|
| `json.sfd` | the calls and their registers: the source of the headers |
| `include/libraries/json.h` | types and constants |
| `include/proto/`, `inline/`, `clib/` | generated by `make headers` |
| `src/json.c` | reading, walking, building, writing: plain C, also built on the PC |
| `src/rexx.c` | the ARexx functions |
| `src/lib.c`, `src/start.s` | the library: Resident tag, jump table, ARexx's entry |
| `src/port.h` | memory and files on the Amiga or the PC |
| `docs/guide.md`, `docs/reference.md` | the programmer's guide and the reference |
| `tests/unit.c`, `suite.c`, `fuzz.c` | the PC tests (`tests/pcinc` stands in for the Amiga headers) |
| `tests/jsontest.c`, `jsontest.rexx` | every call on the Amiga, from C and from ARexx |

## State

**0.1b1, 2026-10-16.** Tested:

- **On the PC:** the unit tests (every call, the edges, a 1,000,000-deep file, a 60 KB string) and
  JSONTestSuite (283 right, 0 wrong; everything read writes back and reads the same in all four
  writing modes), under ASan and UBSan; 7.2 million fuzzed inputs without a fault.
- **In FS-UAE:** `jsontest` and `jsontest.rexx` all passed on the A1200 test machine (68EC020,
  OS 3.2.1, the 020 build) and on the A600 (68000, Workbench 2.05, the 000 build); the guide's
  examples ran as written.
- **Not yet:** the real A1200; a 68060.

**Found on the way:** ARexx (OS 3.2 and 2.05) takes a function library's result string from
**A0**. A result in A1 alone came out as garbage and then a "corrupt memory list" guru; the entry
now gives it in both.
